# Bestway Security Audit

**Review date:** 2026-10-12  
**Reviewed ref:** `migration/django-backend` at `ce67d9624d2d1ef1e78dc8752b408bf1f5770fb4`, plus the shared working-tree state present during review  
**Overall:** **Not security-clean; remediation is required before describing dependencies as current.** The main verified issues are vulnerable pinned runtime dependencies and a boundedness/availability weakness in the Next API proxy upload path. Static configuration contains several good controls. No verified auth bypass or SQL injection was established by this review. The tracked-environment check found templates only; full secret-history scanning was not completed.

## Scope and method

Reviewed the Bestway Node/Nest backend, Next.js frontend, Django parallel backend, security-sensitive auth/JWT/media/upload code, production settings/Compose, package/requirements manifests and GitHub Dependabot alerts. Ran cached/local npm and pip advisory audits and Bandit static analysis; reviewed alert metadata and the flagged code paths; ran focused tests where local dependencies and configuration allowed. The shared checkout already contained unrelated uncommitted work at review start (including an in-progress Django Admin feature in settings, auth backend/forms, admin registrations and tests). Findings about the stable source/lockfiles use the reviewed commit; any statement about uncommitted files reflects their working-tree contents, and those files were not changed by this audit. The report is the only audit-created file.

This is a repository-level static and targeted test review. It is not a penetration test, live infrastructure assessment, secret-provider review, full manual line-by-line assessment of all 8,652 tracked files, or assurance that production matches the reviewed commit.

## Findings requiring action

### High — dependency vulnerabilities in deployed/runtime dependency trees

1. **Next.js 16.3.6 is behind its patched release.** The lockfile audit reports the installed range `16.0.0–16.3.7`, with `16.4.0` available in the local audit metadata; the reviewed GitHub alert for `GHSA-cjq9-62q9-8jv4` specifies patch `16.3.8`. Six current Next advisories are open in Dependabot: `GHSA-3w37-wq28-93x7`, `GHSA-4jqv-mc3x-m676`, `GHSA-39w2-rjm5-chcv`, `GHSA-f87g-xv8r-7p7x`, `GHSA-mcj8-r9mp-w47p`, `GHSA-cjq9-62q9-8jv4`. Some require specific features (Cache Components/Draft Mode, Pages Router SSG/ISR, dev MCP, metadata image routes, root catch-all + cached static output, or Image Optimization + remotePatterns). The app uses App Router and has `remotePatterns`; source search did not find Cache Components/`use cache`, metadata image routes, or a Pages Router catch-all. A demo route does use `generateStaticParams`, and `next/image` is present; Image Optimization therefore deserves feature-specific review. Exposure for each feature is conditional, but the pinned version remains unpatched. **Upgrade to a supported fixed Next version (at least 16.3.8; preferably current supported patch), review actual feature gates, and rerun the production build/tests.** Evidence: [frontend/package.json](frontend/package.json), [frontend/package-lock.json](frontend/package-lock.json), [frontend/next.config.ts](frontend/next.config.ts#L25-L37). Advisories: [Next.js security release](https://nextjs.org/blog/september-2026-security-release), [GHSA-cjq9-62q9-8jv4](https://github.com/vercel/next.js/security/advisories/GHSA-cjq9-62q9-8jv4).

2. **PyJWT 2.11.0 and Django REST Framework 3.16.1 are pinned with open advisories.** Local pip-audit reports 2 DRF issues fixed in 3.17.2 and 16 distinct PyJWT advisory IDs; Dependabot currently reports 16 open PyJWT alerts for 2.11.0, including critical `GHSA-ffc3-869f-jxw9` (fixed 2.14.0) and highs `GHSA-9v7f-9g4p-ffgj`, `GHSA-p4g4-x82p-q773`, `GHSA-xgmm-8j9v-c9wx` (fixed 2.14.0 or 2.13.0 depending on issue). Several PyJWT advisories require PyJWKClient, mixed HMAC/asymmetric algorithms, untrusted JWKs, detached JWS, or reused mutable `options`; the found app decode is explicitly HS256-only with a secret. The direct decode issue `GHSA-hxm8-2xgr-2p9m` concerns non-canonical serialization and becomes a control bypass if raw JWT strings are used as revocation identity; audit this composition. The 2026 DRF advisories include upload-memory-limit bypass and AdminRenderer data disclosure in certain invalid-write cases. **Upgrade PyJWT to a currently supported fixed release and DRF to >=3.17.2; test behavior and inspect any newly added JWT call sites.** Evidence: [backend-django/requirements/base.txt](backend-django/requirements/base.txt#L1-L7), [backend-django/common/auth/jwt.py](backend-django/common/auth/jwt.py#L12-L20). Sources: [PyJWT changelog](https://pyjwt.readthedocs.io/en/stable/changelog.html), [GHSA-2m8g-3cmr-wg3w](https://github.com/advisories/GHSA-2m8g-3cmr-wg3w), [GHSA-g47c-3xmw-q6m2](https://github.com/advisories/GHSA-g47c-3xmw-q6m2), [PyJWT advisories](https://github.com/advisories?query=PyJWT).

3. **NestJS SSE advisory is version-relevant but no vulnerable SSE path was found.** The package lock resolves `@nestjs/core` **10.4.22**, within the advisory’s affected `<=11.1.17` range. Exploitation requires application use of SSE with attacker-controlled event `type`/`id`; source search found no `@Sse`, `MessageEvent`, or `text/event-stream` route. Therefore this is an affected dependency, but the documented application-level trigger was not found. **Upgrade within a fixed Nest release line and reassess if SSE is introduced.** Evidence: [backend/package.json](backend/package.json), [backend/package-lock.json](backend/package-lock.json), [backend/src/main.ts](backend/src/main.ts).

4. **Other runtime dependency advisories:** backend `proxy-addr` is reported critical (`<2.0.8`; fixed `2.0.8`); frontend `sharp` is high (`<0.35.5`; fixed `0.35.5`); `source-map-js` high (`<1.2.2`; fixed `1.2.2`) is in both JS trees. Upgrade via tested lockfile changes. The proxy-addr concern is trust-IP parsing; production Nest code does not enable Express trust proxy in `main.ts`, which mitigates the described spoofing path, but confirm any platform/proxy setup does not set it externally. `source-map-js` DoS requires processing hostile indexed source maps; determine reachable production path. Sharp’s advisory is conditional on parsing attacker-controlled images via vulnerable librsvg. **Update them anyway and validate production code paths.** Evidence: [backend/package-lock.json](backend/package-lock.json), [frontend/package-lock.json](frontend/package-lock.json).

5. **Development/test dependency alerts are open:** `tinypool` critical (frontend test tree), `pypdf` has 8 highs, and `pytest` medium. These do not imply the production app directly exposes the vulnerable code, but can affect CI/developer environments or build supply chain. Upgrade test tooling and pypdf; keep untrusted documents out of the affected parsing flows. Evidence: frontend lock and [backend-django/requirements/dev.txt](backend-django/requirements/dev.txt).

### Medium — 500 MB upload can exhaust frontend process memory

The Next catch-all proxy reads the entire body into an `ArrayBuffer` before forwarding. Video/multipart limit is 500 MiB and the Next container is capped at 768 MiB; concurrent uploads can multiply memory use and trigger OOM/restarts, denying service to all web requests. A 10-minute upload timeout extends resource occupancy. This is not a code execution or auth bypass, but it is a credible availability weakness. **Use streaming request forwarding with a bounded concurrency/size policy, or reduce limits and enforce edge-level per-IP/request concurrency; test actual Next runtime buffering behavior.** Evidence: [frontend/src/app/api/backend/[...path]/route.ts](frontend/src/app/api/backend/%5B...path%5D/route.ts#L81-L105), [frontend/next.config.ts](frontend/next.config.ts#L43-L47), [docker-compose.yml](docker-compose.yml#L81-L95), [backend/src/videos/storage.service.ts](backend/src/videos/storage.service.ts#L81-L88).

### Low/Medium — missing upload content-level validation

Video and image uploads check MIME type and filename extension (both client-influenced) and stream the supplied bytes to disk; no content-signature or decoder validation is evident in the upload path. This permits mislabeled/corrupt content and potentially unsafe media depending on downstream browser/player/thumbnail processing. **Validate file signatures and decode/re-encode images; consider malware scanning and strict serving headers.** Evidence: [backend/src/videos/storage.service.ts](backend/src/videos/storage.service.ts#L89-L107), [backend/src/videos/videos.service.ts](backend/src/videos/videos.service.ts#L88-L99). Django media similarly uses extension/MIME checks in [backend-django/apps/core/mock_media.py](backend-django/apps/core/mock_media.py#L43-L74).

## Positive controls verified

- Production Django settings fail startup without long non-default secrets, explicit non-wildcard `ALLOWED_HOSTS`, Redis, CORS origins; enable HTTPS/HSTS, secure cookies, nosniff, and frame denial: [production.py](backend-django/config/settings/production.py#L7-L53).
- Django JWT decode pins `algorithms=['HS256']`, requires `sub`, `exp`, `iat`, and checks active user in DB: [jwt.py](backend-django/common/auth/jwt.py#L8-L20), [authentication.py](backend-django/common/auth/authentication.py#L11-L19).
- Self-registration accepts only student/parent; Django auth routes have scoped rate limits; Nest has auth throttles: [backend-django/apps/core/views.py](backend-django/apps/core/views.py#L73-L110), [backend/src/auth/auth.controller.ts](backend/src/auth/auth.controller.ts#L23-L26), [backend/src/app.module.ts](backend/src/app.module.ts).
- Search-generated SQL fragments reviewed in Bandit findings use fixed code-owned column/where fragments; bound values are parameterized. No evidence of exploitable SQL injection from those flagged locations.
- Signed media links use HMAC and constant-time comparison in Nest; storage paths have containment checks: [backend/src/videos/stream-token.service.ts](backend/src/videos/stream-token.service.ts#L11-L49), [backend/src/videos/storage.service.ts](backend/src/videos/storage.service.ts#L28-L34).
- Git index contains only `.env.example` templates, not `.env` files. A complete secret-scanner/history scan was not available in this environment, so this is not proof that no credential was committed historically or that deployment secret stores are safe.
- Django Stage B media route binds student listening audio to an owned active attempt and checks timing/playback state: [backend-django/apps/core/mock_media.py](backend-django/apps/core/mock_media.py#L64-L111).

## Static scanner triage

Bandit recorded 10 findings. SQL `B608` reports are false positives in the reviewed sites: SQL clauses/column identifiers are selected from fixed internal choices while values are passed separately as parameters. `B310` on Telegram delivery uses a code-constructed HTTPS URL with a non-user-controlled API method and a fixed healthcheck loopback URL; no arbitrary URL input is involved. The subprocess call runs the same Python module with an executable argument list, bounded input size, timeout, CPU/address-space limits on Linux; no shell interpolation was found. The `B110` exception/pass in assessment worker is low-confidence and should be reviewed for observability, not treated as a security bypass without its precise failure context.

Authenticated GitHub Dependabot snapshot: **41 open alerts** across prod/dev packages. Counts vary by advisory aliases and scanner timing; upgrade and rescan current lockfiles.

## Recommended order

1. Upgrade Next, DRF, PyJWT, proxy-addr, sharp, source-map-js; regenerate and review lockfiles; rerun npm/pip audits and CI.
2. Remove full-body buffering for large uploads or strictly bound concurrent/maximum upload memory pressure.
3. Validate image/video file signatures and handling; test malicious/corrupt media through actual serving and browser/player.
4. Review/upgrade dev dependency alerts; isolate CI permissions and avoid parsing untrusted PDF input in affected pypdf versions.
5. Run Django security/auth/permission/media/attempt suites with a disposable local Postgres and Redis configuration; conduct a production configuration and external perimeter test before cutover.
6. Reconcile the edited worktree before any follow-up fixes: this shared checkout already had unrelated modifications and untracked files before the audit. No source files were changed by the audit.
